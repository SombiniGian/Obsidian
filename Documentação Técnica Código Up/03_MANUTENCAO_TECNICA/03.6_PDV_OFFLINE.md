## PDV Offline

---


### Conceito:

Ponto de venda (PDV) autônomo, com base de dados própria. A instalação desta estação deve ser feita como SERVIDOR.  

        #### OBJETIVO DA FERRAMENTA:Possibilitar que uma estação de vendas não fique conectada ao servidor para executar as tarefas básicas. Ou seja, a máquina fará as vendas independente se o servidor (retaguarda) está ligado ou não.

#### Replicação de Dados:

A estação OFFLINE de tempo em tempo irá replicar os dados das vendas, notas fiscais e novos clientes cadastrados.  

Na estação OFFLINE teremos uma configuração para que ao iniciar o dia, ou um novo caixa, os dados sejam atualizados.  
Essa ferramenta buscará somente os dados alterados no servidor para evitar grande volume de informações desnecessárias.

OBS: TODO cadastro de novos produtos, naturezas, tabelas, etc. Deverá ser feito no retaguarda, e através da ferramenta de replicação de dados, atualizamos na estação offline.

    ![](images/image44.png)
6. Defina a rotina de atualização dos dados. Podendo automatizar a troca de informações entre o PDV OFFLINE e o RETAGUARDA. A opção de Obrigar Atualização e Envio automático.  
    ![](images/image68.png)
7. A Série NF deve ser diferente entre as estações para que não haja duplicidade da NF.

3. Faça a instalação do sistema Up com base de dados utilizando a mesma versão de firebird utilizada pelo servidor retaguarda.

### Atenção com Ip e Porta para Conexão

- Se utilizamos o Servidor retaguarda e o pdv off na mesma rede, configuramos na estação o IP da máquina Servidor retaguarda.
- Se utilizamos em computadores que não estão na mesma rede, instalamos e configuramos a ferramenta ZeroTier ou VPN e nas configurações do PDV off o IP do Servidor retaguarda disponível no ZeroTier em que está o retaguarda e a porta do Servidor Força de Vendas.
- Se o Servidor Retaguarda está em uma máquina na nuvem, utilize o endereço ip do servidor em nuvem e a porta do Servidor Força de Vendas.
- Se precisamos utilizar a maquininha para vender externamente e o nosso sistema funciona local é necessário ligar para a provedora de internet e solicitar um ip fixo, desta forma basta utilizar esse ip.

## Topologia e Cenários de Operação

### Conceito e Finalidade

O **PDV Offline** é um ponto de venda autônomo que opera com um banco de dados local. Sua principal função é resolver a dependência de conectividade constante com o servidor central, permitindo que a operação de venda continue mesmo sem acesso à internet ou à rede local.

* **Funcionalidades Suportadas:**
    * Realização de vendas (PDV).
    * Processamento de devoluções de venda.
    * Recebimento de contas a receber.
    * Cadastro de novos clientes.
* **O que não faz:** Operações de retaguarda como "Entrada de Nota Fiscal" devem ser realizadas na nuvem e, posteriormente, replicadas para o PDV offline através da sincronização de dados.

### Cenário A — Multiempresa (Locais Distintos)

* Ideal para cadeias (ex: restaurantes) em que cada CNPJ está em um endereço físico diferente.
* Cada unidade possui seu servidor offline (banco de dados local).
* A nuvem atua como orquestrador e centralizador de dados.

### Cenário B — Supermercado (Alta Disponibilidade)

* Objetivo: Evitar a parada total em caso de falha na rede interna.
* Cada caixa atua como um "servidor" independente.
* Se o servidor central cair, os caixas individuais continuam vendendo. Se um computador estragar, os outros 9 permanecem operacionais.
* **Nota Técnica:** Cada estação configurada como PDV offline possui sua própria vida autônoma. Eles não conversam entre si, garantindo isolamento total de falhas.

### Sincronização e Regras de Negócio

* **Sincronização Bidirecional:** Quando o link de rede é restabelecido, o PDV offline envia as vendas realizadas para o servidor na nuvem (ou local) automaticamente.
* **Limitação de Visibilidade:** Como o PDV offline trabalha de forma isolada, um caixa (PDV1) não enxerga as vendas feitas em outro caixa (PDV2) em tempo real. As informações só são consolidadas e visíveis globalmente quando replicadas para o servidor central.
* **Conectividade:** O PDV offline é indispensável em locais com infraestrutura de rede instável (ex: conexões Wi-Fi instáveis em mercearias/sorveterias), garantindo que a operação de vendas não seja interrompida.

## Configuração de Estações e Infraestrutura

### Configuração de Estações de Trabalho

A instalação do PDV Offline é segmentada em duas funções distintas dentro da rede local:

* **Servidor Local (PDV Offline):** A estação que recebe a instalação do banco de dados local. Esta máquina torna-se o núcleo de processamento do PDV para aquela unidade física.
* **Estações (Terminais):** Máquinas adicionais utilizadas para realizar as vendas. Elas não possuem banco de dados próprio, sendo configuradas para apontar diretamente para o *Servidor Local*.
* **Segregação de Cargas:** O sistema permite definir qual computador será responsável por processar a carga de dados. Essa configuração deve ser centralizada para evitar conflitos de atualização e garantir que o *Servidor Local* mantenha o *dataset* sempre atualizado a partir da nuvem.

### Independência e Autonomia

O principal valor desta arquitetura é a capacidade de sobrevivência do ponto de venda.

* **Vida Autônoma:** Uma vez configurado como PDV Offline, o terminal possui uma base de dados completa (produtos, preços, clientes).
* **Resiliência a Falhas:** Caso ocorra a queda da rede (corte do cabo de rede ou falha na infraestrutura de internet), o sistema não interrompe a operação. O PDV continua permitindo vendas, devoluções e recebimentos normalmente, pois consulta exclusivamente o banco local.
* **Isolamento de Erros:** Em cenários como supermercados com múltiplos caixas, a falha de uma estação (ou a interrupção do servidor central) não paralisa as demais. Cada PDV Offline preserva sua autonomia, evitando o efeito cascata de parada de operação.

### Lógica de Replicação de Dados

A sincronização entre o PDV Offline e a retaguarda na nuvem é gerenciada pelo motor de replicação:

* **Upload em Background:** As transações realizadas em modo offline são armazenadas localmente. Assim que a conectividade com a nuvem é detectada, o sistema inicia automaticamente a replicação dos dados pendentes para o servidor central.
* **Limitação de Escopo:** É vital compreender que a replicação é um processo assíncrono. Vendas realizadas em um terminal offline não são visíveis em outros terminais ou na nuvem em tempo real até que a sincronização seja concluída.
* **Priorização:** O sistema é otimizado para que a operação de venda (frente de caixa) tenha prioridade máxima, relegando as tarefas de sincronização para momentos em que o processamento do PDV não seja afetado.

## Gatilhos e Personalização do PDV

O sistema oferece ferramentas avançadas de automação que estendem a capacidade do PDV Offline:

* **Gatilhos (Triggers/SQL):** Permitem executar comandos SQL baseados em eventos (ex: "ao incluir pedido"). Podem ser utilizados para validar grupos de produtos proibidos para venda a prazo, bloqueando automaticamente a operação se uma regra de negócio for violada.
* **Tela Personalizada:** O PDV moderno é altamente customizável. O administrador pode alterar a posição de elementos, cores, fontes e atalhos, adequando o software às necessidades específicas de produtividade do operador (ex: mapear teclas de atalho de sistemas anteriores para facilitar a transição).
