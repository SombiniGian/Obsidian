# Controle de Impressões

> **Escopo:** Associar relatórios customizados do gerador a qualquer tela de cadastro ou movimentação; passagem do parâmetro `ID`; permissão por operador.
>
> **Pré-requisitos:** Layouts já criados/compilados no **Gerador de Relatórios**.

---

## Conceito e funcionamento

O **Controle de Impressões** permite vincular layouts customizados a interfaces do ERP (clientes, ordens de serviço, pedidos, notas fiscais etc.).

Ao acionar **Imprimir** no formulário, o sistema exibe uma lista flutuante com os templates assinados para aquele contexto.

### Casos de uso comuns

- **Cadastro de clientes:** ficha cadastral para assinatura ou colheita de dados com foto.
- **Ordem de Serviço (OS):** via simplificada de “Entrada de OS” (sem valores fiscais/peças) e via detalhada de “Saída de OS” (precificação e termos de garantia).
- **Movimentações comerciais:** espelhos de pedidos de venda ou faturamento conforme o segmento.

---

## Vinculação de relatórios às interfaces

- **Acesso:** botão/menu **Controle Impressões** na barra de ferramentas da tela que receberá os relatórios.

### Fluxo de associação

1. Abra o formulário desejado (ex.: **Ordem de Serviço**) e clique em **Controle Impressões**.
2. **Incluir**.
3. Selecione na listagem o relatório do **Gerador de Relatórios** (ex.: `OS - Entrada Simples`).
4. Confirme.
5. Repita para múltiplos layouts na mesma tela (ex.: `OS - Saída Completa`).

---

## Passagem de parâmetros (ID)

Para o gerador renderizar só o registro selecionado em tela, o ERP injeta a chave primária do registro ativo na variável global obrigatória **`ID`**.

No dataset do relatório, a consulta SQL deve filtrar com essa variável nativa. Exemplo de sintaxe na fonte:

```sql
SELECT * FROM ordens_servico WHERE id_os = :id
```

A cláusula `WHERE` deve usar o parâmetro dinâmico na forma **`:id`**.

---

## Controle de acesso por operador

No vínculo do relatório no painel, o campo **Usuário** restringe a visibilidade: se associado a um operador específico, o layout só aparece sob as credenciais daquele usuário.

---

## Pontos críticos e validações

1. **Nomenclatura do parâmetro:** o gerador é sensível ao nome da variável. Usar `:id_os`, `:codigo`, `:ID_OS` ou outros termos **não** é reconhecido pela integração — o relatório falha ou retorna listagem em branco. Use estritamente **`:id`**.
2. **Processamento em lote:** ao confirmar múltiplos layouts de uma vez, o sistema gera sessões de visualização/impressão consecutivas e apartadas.
